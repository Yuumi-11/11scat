# 双人音乐小窗：交付能力与验收边界

## 接入结论

本轮基于 main 的 9c615e0 开发，继续使用现有 VPS、房间身份认证和 /data 持久化，不迁移托管，不接触制作中的教室外观分支。

当前没有已验证的网易云账号授权、跨客户端当前播放状态或一起听同步提供者。现有本机探测记录确认该设备的网易云 3.1.23.204814 未发布可枚举的 GSMTC 会话；UI Automation 的歌曲与按钮读取仅是探测，进度、后台稳定性和远程控制未验收。普通网页不能据此读取桌面客户端。

社区的 [NeteaseCloudMusicApi 文档](https://binaryify.github.io/NeteaseCloudMusicApi/)包含“一起听”相关接口，但这不是网易云官方 OAuth/同步服务承诺，也没有本项目的双端实测。参考其项目文档不等于已完成接入。本轮不读取网易云 Cookie，不部署逆向代理或模型，不要求用户把账号密码交给本站。

因此本次正式页面采用用户允许的**网易云外部邀请模式**：在网易云生成一起听邀请，粘贴 HTTPS 链接和邀请中的歌曲名，经另一位成员明确接受，再点击“去网易云一起听”。本站只确认邀请被接受；是否进入网易云一起听由网易云完成，本站不会显示“正在一起听”。

## 正式可用

- 成员卡片旁的耳机“音乐”入口，保留原成员操作与邀请链接。
- 浅蓝小窗、约 400 px 展开宽度，300 px 两行摘要；窄屏左右留白。
- 标题栏拖动、方向键移动、按身份保存位置、尺寸变化及恢复时限制在可视区域。关闭/收起不会取消邀请。
- 独立的共享偏好，默认关闭；邀请接受不会开启共享。关闭共享撤销当前网站邀请，界面不把旧曲目信息当作当前播放。
- 房间成员之间的真实持久化邀请、接受/拒绝、取消、十分钟过期、结束。非参与者看不到邀请，不能替另一方接受。
- 接受前说明跟随谁、可能切歌，以及仍需在网易云确认。
- 账号未接通、未共享、无曲目、离线、状态不可用分别呈现；本轮实时来源未接通，因此不会产生假的“正在播放”。

## 尚未接通

网易云账号绑定、自动采集双方当前曲目、真实共同进度、站内播放/暂停、确认原生一起听状态。本轮不宣称端到端网易云同步完成。要启用这些能力，仍需选择并实际验收双方可使用的播放状态来源与受支持的同步适配器。

共同歌曲卡片与只读跟随方、控制方、结束后恢复两行、共同摘要等组件已经实现，但正式 API 不提供已验证会话，所以不会激活该界面。

## 截图与演示隔离

`/music-preview` 只在 development 环境可用；production 返回 404，并由 HTTP 测试验证。演示页使用与正式页面相同的 React 组件，所有状态都保留“交互预览 · 演示数据，非真实同步”标识。截图是实际渲染和点击后的组件截图，不是静态效果图；歌曲和共同状态均是标注过的演示数据，不能作为真实接入证据。

截图保存在工作树 outputs/music。公开正式页面不含演示入口、查询参数开关或种子歌曲。

## 验证

领域测试覆盖双身份邀请、角色权限、共享默认关闭、拒绝/取消/结束、过期、并发重复邀请、进程重建读取、拒绝外部 URL，以及关闭共享后不投影旧曲目。实际 HTTP 测试覆盖认证、跨站拒绝、缺 Origin 拒绝、两身份接受、无伪造同步、结束与 production 演示页 404。

浏览器已检查独立卡片、邀请等待、接受前说明、共同卡片、跟随方没有播放按钮、摘要播放不展开、收起/展开、关闭后重新打开不结束会话、拖动和屏幕缩窄后位置回收。390 px 布局中卡片 366 px，scrollWidth 与 clientWidth 相等。

真实网易云的双账号播放、原生一起听链接和实体手机尚未端到端验收，不使用演示结果替代。
