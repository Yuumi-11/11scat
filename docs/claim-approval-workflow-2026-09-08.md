# 认领与审批工作流程

更新时间：2026-09-08

## 本次行为

协作区保留上方公共任务板和下方成员收集箱。认领其他成员的任务时，原任务保留在原账户，网站在认领者收集箱中创建同标题任务，并保存双方的关联关系。拖动到某位成员区域相当于为该成员安排认领；旧的跨账户删除原任务、移回公共区等转移操作已停用。已经进入流程的任务不再接受再次认领或拖动；按后续指示，所有成员均可修改详情，设置同步到关联任务。

公共任务的审批人固定为发布者，不随其他成员编辑标题而改变。公共任务被认领时，会分别在发布者和认领者的收集箱建立任务，公共便签继续保留并显示进度；发布者认领自己的公共任务只建立一项。审批通过后，关联任务完成，公共便签从待办区域移除，流程记录继续保留。旧公共任务仅在原创建记录能够确定发布者时补充归属，无法确定时不会猜测审批人。

认领者在“工作流程”中提交完成，原任务所属成员或公共任务发布者负责通过或打回。提交和打回均不勾选滴答任务；打回可以附评语与附件，认领者可以再次提交。审批通过后，网站依次向两边滴答账户发送完成请求，并记录各自结果。这两个外部请求无法形成同一数据库事务，因此若只有一边成功，流程会显示尚未完成同步，保留已成功的进度并允许核对后继续。

附件可通过文件选择或拖入说明区域上传，单文件限制 20 MiB，每次提交最多 10 个；每流程附件总量限制为 100 MiB，全室总量为 1 GiB，包含已上传但未提交的文件。超量会停止上传，不会无限占用服务器空间。附件和评语保存在网站数据目录，流程中可下载；尚未提交的附件仅上传者可读，提交后自习室成员可读。中断和超限上传会清理本次未完成文件，已提交的流程历史不会自动过期。

原任务在滴答中的附件、评论和专注历史保留在原任务上，当前 API 复制的是标题、说明、日期、优先级等支持字段；网站审批附件独立保存。父子任务关系暂不支持单独跨账户认领，避免关系与完成含义发生改变。

## 请求中断与重复操作

创建前保存当前收集箱任务编号集合，发出创建请求后先保存滴答返回的实际编号，再读取核对。响应丢失时先查已保存编号，必要时仅在创建前集合之外存在唯一完整匹配项时接续，不再次盲目新增。编号不明确或有多个候选时保持“正在建立”，原任务保留。

提交时记录双方任务版本，审批前重新读取并核对。任务在滴答 App 中于提交后变更时，要求打回后重新提交；通过网站编辑详情则自动回到进行中，避免审批已经变化的内容。审批请求及每边的完成进度持久保存；同一请求重发不会重复记载审批事件。普通任务完成响应丢失时可以读取已完成状态后接续，重复任务的完成响应若不明确，则停止再次勾选，防止推进到下一周期。重复任务真实周期行为尚未在用户账户验收。

网站原有个人任务板的完成接口也会检查工作流程：原任务所属成员或公共发布者可以直接完成双方关联任务，认领者仍须从协作区提交审批。这里只约束网站内操作；滴答 App 内手动勾选联动按用户最新要求暂不实现。

## 完成权限与详情编辑的后续更新

2026-09-08 后续调整允许原收集箱所属成员或公共任务发布者直接完成双方关联任务，并在流程中记录完成结果；认领者仍提交审批。所有成员均可编辑任务详情，待审批流程修改后需重新提交，设置同步保留失败恢复进度。无日期任务的认领按钮移入标题行，完整行为与验证见[后续实施记录](workflow-flexibility-2026-09-08.md)。

## 旧转移记录清理

用户最新指示为直接删除旧记录，已替换此前的回退与待核对处理。新版收到成员请求时自动删除旧版转移历史及其异常提示，不再显示“核对”按钮；保留收集箱任务和新的认领审批流程。具体范围、触发方式及测试见[协作区最新调整](collaboration-simplification-2026-09-08.md)。生产私有数据未直接读取，不报告实际清理数量。

## 外部勾选联动：暂缓实施

用户因服务器负担明确要求暂缓这部分，本次没有增加外部完成监测、后台任务扫描或自动恢复未完成。页面既有的版本检查和打开协作区后的刷新机制保留；版本检查读取本地协作记录，不逐个查询滴答完成状态。提交和审批动作会按需核对对应任务，以保证流程操作安全。

2026-09-08 查阅[滴答官方 Open API 文档](https://developer.dida365.com/docs/openapi.md)，文档列出任务查询、筛选和已完成查询等接口，当前文档未列出可用于此需求的 webhook，也未列出独立“恢复未完成”接口。任务批量更新的状态字段不等于已经验证能够恢复完成任务，暂不依此实现自动反勾选。

后续优先考虑“进入流程时检查 + 用户手动同步”：只在用户打开某条流程或主动点击时查双方关联任务，成本随实际使用增长，但关闭页面时不保证同步。另一种方案是只为在线房间中未结束的流程做集中检查，按账户合并请求、限制频率并在离线时停止，避免每个页面各自重复查询；它仍属于轮询，需要先测量接口限额和实际流程量后再决定。若滴答后续提供正式事件订阅，可以重新比较事件驱动方式，目前不能承诺即时联动。

## 验证范围

服务测试涵盖权限、并发认领和重复请求、实际任务编号、重启恢复、打回重新提交、审批版本冲突、部分成功和重复任务响应丢失。真实 Next HTTP 服务使用隔离数据目录与模拟滴答接口，验证了认领到审批的完整链路、原任务板完成保护，以及附件鉴权、下载、超限和中途权限变化。

页面验收使用本地测试成员与虚构任务，生产代码中未加入测试入口或模拟滴答行为。生产真实双账户操作、移动端文件拖放与滴答重复任务周期行为仍需实际验收。

本轮最新构建通过，58 项测试全部通过，修改范围的 ESLint 和差异格式检查通过。测试使用虚构成员和模拟滴答接口，不会修改真实账户。

本地浏览器已验证个人认领后双方原位展示、流程打开、认领者提交完成和审批者按钮。尝试通过浏览器上传虚构测试附件时，自动审批拒绝该操作，且要求不要继续或申请批准；没有重试或绕过。附件上传与下载的 HTTP 自动测试已通过，浏览器文件选择上传和操作系统拖入附件仍未验收。
随后本地页面只读检查也被自动审批拒绝，浏览器验收已停止，因此本轮未取得可交付的真实效果截图。
