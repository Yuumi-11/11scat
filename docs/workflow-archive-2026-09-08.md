# 工作流程归档与自行收取任务

更新于 2026-09-08，按用户最新要求调整。滴答 App 中直接勾选后的处理方案仍处于讨论阶段，本次没有增加外部勾选监测或改变其现有行为。

## 默认列表与归档

打开“工作流程”时默认仅显示未完成流程，包含自己认领的任务与他人认领的任务。正在建立、进行中、待审批、已打回及正在确认完成均属于未完成状态，沿用自习室原有可查看范围。

已完成任务通过“已完成归档”按钮进入单独列表，按钮显示归档数量。归档列表可以打开任务查看历史及详情，也可以返回未完成流程；已完成记录不再混入默认列表。处理当前流程时仍可看到刚完成后的详情和结果，返回列表后按相应列表的状态筛选。

## 自己发布的公共任务由自己认领

认领后在发布者自己的收集箱创建一条普通未完成任务，完整保留支持的任务字段。确认创建成功后从公共任务板移除便签，不要求自我审批，不显示工作流程或认领标签。用户可以按普通个人待办编辑与完成这条任务。

其他成员之后认领该收集箱任务时，会建立正常的跨成员认领流程：原所属成员负责审批，认领者获得关联任务，后续沿用现有提交与审批规则。再次认领的来源是个人收集箱中的任务，原公共便签不会重新出现。

## 重复请求与旧记录

服务保存创建回执以处理重复点击及网络中断；该回执不作为工作流程展示。同一请求重试不会重复创建，创建未确认时保留公共任务及继续处理入口，只有发布者可继续将其放入自己的收集箱。接收方编号不明时先核实已有任务，不根据标题直接重复新增。

此前已经建立的自我认领记录，在新版收到成员请求后按相同展示规则处理：已建立的普通任务解除流程限制，公共便签移除，滴答中的完成状态保留。仍有创建、修改或完成同步未确认的旧记录保留重试进度，不丢弃此前已发出的请求；旧附件及回执数据也不会因调整列表而被删除。

## 验证

生产构建、类型检查与修改文件的 ESLint 通过，全项目 91 项测试通过，无跳过项。测试覆盖默认列表与归档的内容隔离、自行收取后的普通任务行为，以及其他成员随后认领的完整流程；另验证重复请求、创建响应丢失后的恢复和旧自我认领记录转换。

隔离的 Next HTTP 服务验证自行收取接口返回普通操作结果，不触发审批弹窗；随后读取收集箱时没有流程标记，其他成员仍可建立新的正常流程。测试使用虚构成员和模拟滴答接口，真实账号与浏览器实机布局仍待实际验收。
