# 认领任务的完成权限与详情编辑

更新于 2026-09-08，按用户最新截图与说明实现。此前对已认领任务统一禁用勾选、禁止编辑详情的方式已调整；后续权限更正：既非原任务所属成员或发布者、也非认领者的成员只能编辑信息，不能勾选完成。本次仍不检测滴答 App 中的外部勾选，也没有新增轮询。

## 勾选的实际行为

| 任务情况 | 操作成员 | 点击勾选后的行为 |
| --- | --- | --- |
| 未被认领的个人任务 | 原收集箱所属成员 | 直接完成任务所属成员收集箱中的该任务，不建立审批流程 |
| 未被认领的公共任务 | 公共任务发布者 | 从公共任务板移除该待办，不建立审批流程 |
| 已认领的个人任务 | 原收集箱所属成员 | 直接完成双方关联任务，流程记录直接完成及同步结果 |
| 已认领的公共任务 | 公共任务发布者 | 直接完成发布者与认领者的关联任务，公共待办在同步完成后移除 |
| 已认领任务 | 认领者且非原所属成员或发布者 | 仍通过提交完成、审批的方式结束；不能使用普通勾选绕过审批 |

无关成员不能勾选任何任务，包括尚未被认领的待办；页面隐藏其勾选按钮，服务端返回 403，但详情编辑继续开放。公共任务无法确认发布者时不开放勾选权限。失败完成请求的重试同时核实当前操作者与原请求发起者，旧版本遗留的越权请求也不能继续执行。

原任务所属成员或发布者的直接完成通道同时覆盖协作卡片、流程详情，以及主页个人任务板的勾选入口。“发起者”按原任务归属或公共任务发布者判定，替其他人拖动安排任务的成员不会因此取得原任务的审批身份。

进行中、待审批和已打回的流程均可由上述成员直接完成，无须先让认领者提交。流程会记录谁发起了直接完成，双方都可在工作流程中查看；只有关联任务的完成结果处理成功，流程才显示已完成。网络失败导致部分任务已完成时保留进度，继续处理会跳过已经确认的完成结果。重复任务的响应不明时仍停止重复勾选，防止误完成下一次任务。

## 详情编辑

所有已登录的自习室成员均可打开卡片的三个点进入详情，也可通过工作流程里的“详细设置”修改任务。已完成的流程仍提供此入口，用户可以补充说明；修改详情不会恢复为未完成。

一次保存会同步流程中的任务字段，以及双方收集箱中的关联任务；公共任务还会同步公共便签。日期、提醒和重复设置属于同步范围，其他原有可编辑字段继续使用相同编辑表单。任务已经有人认领后，新的认领和直接删除仍被限制，详情编辑不再受该限制。

若任务正处于待审批状态，修改成功后回到进行中，需要认领者按最新内容重新提交；此前说明和附件仍保留在历史中。修改同步尚未完成时暂不接受提交或审批，避免按部分更新的数据完成任务。此时任意成员都能继续同步，或核对任务现状后保存新的设置；后续设置会留下替代记录。

服务先保存修改请求，再按关联任务逐项处理。每次实际更新前核对任务版本，网络响应丢失时读取已保存内容，避免重复写入；已明确同步的任务不会被无条件重复覆盖。并发编辑使用流程版本识别过期请求，过期页面需要刷新后再保存。正在建立的流程会先核实原来的任务创建结果，再应用已保存的新设置，不会因改名或改日期重复创建任务。

## 卡片布局

对方无日期待办的“认领”移到标题行右侧，位于详情按钮左侧。无日期、无优先级及无重复提示的任务不再为认领按钮单独保留下一行，因此能在同样高度内显示更多待办。有日期任务与公共便签继续使用原来的认领位置。

## 验证范围

生产构建、类型检查及修改文件的 ESLint 通过，全项目 88 项测试通过，无跳过项。新增验证覆盖未认领任务的所属权限、无关成员编辑权限和旧完成请求重试权限，以及原任务所属成员直接完成的角色检查和重放请求；同时验证了详情修改跨账户同步、待审批后修改、创建结果不明及部分完成后的恢复。

隔离的 Next HTTP 服务验证了详情编辑端点与主页勾选入口，使用模拟滴答数据，不操作真实账户。组件渲染测试验证不同成员和流程状态下均有详情入口，只有原所属成员或发布者有直接完成按钮。浏览器实机布局与真实滴答账号仍需实际验收，不能用这些测试替代真实界面截图。
